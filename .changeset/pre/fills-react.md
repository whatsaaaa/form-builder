`useJsonForm` runs the fills of the definition, like the `fills` of `@whatsaaaa/form-builder-fills`: each new value of a trigger sets the fields of its fill, and a trigger that loses its value blanks them. The values of a map are in the initial input on the first render, and the fills of sources the form starts with run once it is mounted, as values it starts with, so the form isn't dirty. A trigger that `initialInput` has a key for fills nothing as the form starts. `jsonForm.fills` says what waits for a source, `pending` and `isPending(path)`, and is a new object only when that changes, so disable the submit button while `fills.pending` isn't empty. Each value field component gets a `pending` prop in a form with fills. The new option `onFillError` gets each error of a fill, with the trigger and its value, and without it the error is thrown like an uncaught one. Next and `goTo()` forward wait for pending fills before they validate, and move among the steps on show for the values the fills set. `jsonForm.reset()` resets the whole form, like Formisch's `reset` with the same options but `keepInput`, with an `initialInput` that goes over the definition's defaults like the option's, and starts the fills again, as when the form was mounted, so the next value sets every field the user hasn't edited since, and the steps from the first one. `FillsState` and `FillErrorInfo` are exported. Every rule is in https://whatsaaaa.github.io/form-builder/frameworks/react#fills.
