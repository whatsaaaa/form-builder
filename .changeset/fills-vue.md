`useJsonForm` runs the fills of the builder's extensions, like the `fills` of `@whatsaaaa/form-builder-fills`: each new value of a field with `fills`, like a profile picked from a select, sets the fields it names with Formisch's `setInput`. A field that starts from its `default` fills in the others as the form starts: the values of a `map` are in the initial input, and those of a `source` are set once the form is mounted, as the values it starts with, so it isn't dirty. A field the `initialInput` option has a key for fills nothing as the form starts, so a saved record keeps its values. `jsonForm.fills` says what is pending, to disable the submit button while values are on their way, each value field gets a `pending` prop in a form with fills, and the steps' Next waits for pending fills before it validates. `jsonForm.reset()` resets the whole form, like Formisch's `reset` with the same options but `keepInput`, with an `initialInput` that goes over the definition's defaults like the option's, and starts the fills again, as when the form was mounted, so the next value sets every field the user hasn't edited since. The new `onFillError` option gets each error of a fill, with its trigger and value; without it, the error is thrown like an uncaught one. Unmounting the form aborts the calls of its sources. `FillsState` and `FillErrorInfo` are exported. Every rule is in https://whatsaaaa.github.io/form-builder/frameworks/vue#fills.
